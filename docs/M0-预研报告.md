## M0-1 headless init 全流程验证 —— ✅ PASSED

**目标**：预写 `~/.openwiki/.env` 后，`openwiki --init -p` 无头化全流程跑通（跳过交互向导）。

**方法**：
1. 从 DSH 凭证文件解析 `DEEPSEEK_API_KEY`（sk-c…e320），写入 `~/.openwiki/.env`：
   ```
   OPENWIKI_PROVIDER=openai-compatible
   OPENAI_COMPATIBLE_API_KEY=<key>            # 复用 DSH 的 DeepSeek Key
   OPENAI_COMPATIBLE_BASE_URL=https://api.deepseek.com
   OPENWIKI_MODEL_ID=deepseek-v4-flash        # 复用 DSH 默认模型
   OPENWIKI_TELEMETRY_DISABLED=1
   ```
2. 用源码构建的 dist（`pnpm build`，产物 `dist/cli/cli.js`）在测试仓库 `plugins/dsh-hello-world` 执行 `node dist/cli/cli.js --init -p -l zh`。

**结果**（exit 0）：
```

… 5 页全部生成 …
Finalizing repository wiki
```
- 向导被跳过（env 预配置生效），agent 直接进入规划 → 逐页生成 → 终局化；

## M0-1b update 收敛验证 —— ✅ PASSED

`--update -p -l zh` 执行成功（exit 0）：直接进入 planning（无新增页）→ finalizing → `.run.json` 删除、manifest 5 页完整、`.last-update.json` 更新为 `command: update`。

**指纹漂移发现**：两次运行均报 "Repository source changed while OpenWiki was running"，根因是**测试仓库嵌在 D:\dsh-openwiki（git 仓库）内，开发期间持续写入 code/ 文件改变了 git status → 源指纹漂移**（指纹 = git 跟踪文件 + 未跟踪文件 + status 码 + HEAD，见 `src/agent/utils.ts::createRepositorySourceSnapshot`）。属测试环境干扰，非 openwiki 缺陷。

**M3 完成态判定影响**：`.last-update.json.status` 因漂移保持 `interrupted`（openwiki 不推进检查点的保护行为）。插件 UI 的"已完成"判定不能只看 status===complete，应结合：
- `.run.json` 不存在（任务已终局）；
- `.page-manifest.json` 存在且有页面（wiki 可用）；
- `.last-update.json.status` ∈ {complete, interrupted}；
- `interrupted` 时展示「有源码变更待更新」提示条（引导 --update）。

**页面 frontmatter（UTF-8 实测）**：`type/title/description/tags/verified/sources/generated` 完整 OKF v0.2 结构；`sources` 为 `repo://<path>` 证据链接（章节来源数据源）。openwiki 同时在仓库根维护 AGENTS.md/CLAUDE.md 的 `OPENWIKI:START…END` 块（自动写入，只改自己的块）。

## M0-2 知识库呈现机制验证 —— ✅ 机制结论（UI 视觉待确认）

**源码结论（已核实）**：`uiConversation` 客户端服务只暴露 `binding()/imageUrl/…`，**无公开的视图切换 API**；会话活动视图存于会话私有 store（`dsh.conversation.<sessionId>`，localStorage 持久化，仅组件内部 actions 可写）；`viewRequest/openView` owner props 只传给当前激活视图组件。**根级 Slot（侧边栏入口）无法程序化切换会话视图。**

**决策（写入实施文档 §4.2.1）**：
- **主呈现 = `shell.overlay` 全屏知识库层**（侧边栏入口直达，插件私有 store 完全可控）；
- **并行保留 `conversation.view` 'openwiki' 视图注册**（会话页头 Tab，原生切换，同一 KbView 组件复用）；
- 视图内导航用 `openView('chat')` owner prop（已验证契约存在，UI 确认中）。

**原型已上线**：动态插件 `owki-1/pkg-1` 运行中，注册了 `sidebar.footer.action` + `shell.overlay` + `conversation.view` + `settings.section` 四处，Host 5 个 RPC handler（runtime/status、model/status、job/status、wiki/tree、logs/tail）。待用户在 GUI 确认：入口显示、Tab 切换、全屏层开合、设置页数据（模型/Key 状态）。

## 重启后验证记录（2026-09，首次重启）

**首次重启结果**：Client 半部已加载（index.html 引导图含 `dsh-openwiki` client.js 引用，bundle 200 可服务），但 **Host 路由 `/dsh-openwiki/rpc` 404**。

**诊断过程**：
1. webServer 服务无方法过滤、`register` 可用（动态诊断插件注册 `/dsh-openwiki-diag` 路由 200 ✓）
2. `settings.get('openwiki')` 未注册 → 包插件 apply 未生效
3. 排除项：包可解析（profile cwd 下 `import('dsh-openwiki')` OK）、模块可加载、patch 行正确（dump-config 含行）、loader 对解析失败会大声报错而 GUI 正常
4. **根因（高置信）**：插件 `inject: []` 无依赖 → cordis 尽早激活 → apply 先于 webServer 行运行 → `ctx.get('webServer')` 为 undefined → 路由注册被守卫跳过

**修复（已构建，待二次重启验证）**：
- `inject: [...plugin.inject, 'webServer']` —— 强制 cordis 先激活 webServer 再 apply 本插件
- 新增启动诊断标记 `~/.dsh/openwiki-boot.json`（applyStarted/webServerPresent/routeResult/settingsResult/bodyApply），重启后无需浏览器即可验证
- 离线功能测试全部保持通过

**待二次重启**：重启后先读 `~/.dsh/openwiki-boot.json`，再探测 `/dsh-openwiki/rpc`。
